# Nano Banana Pro (Gemini 3 Pro Image)

Google DeepMind 의 이미지 생성·편집 모델입니다. 모델 ID 는 `gemini-3-pro-image`.
Gemini 3 Pro 위에 올라가 있어 «생각» 이 기본으로 켜져 있고, 긴 지시를 순서대로 읽습니다.

**태그를 매칭하는 모델이 아니라 문장을 읽는 모델입니다.** 단어를 쉼표로 늘어놓지 말고
장면을 설명하는 문단으로 씁니다. 이것이 이 모델에서 가장 크게 작용하는 차이입니다.

## 잘하는 것 · 못하는 것

| 잘합니다 | 못합니다 |
|---|---|
| 화면 안의 글자 — 포스터·간판·UI 목업, 다국어 | 작게 들어간 글자의 철자, 잔글씨 |
| 레퍼런스 여러 장을 한 장면으로 합성 | 작게 잡힌 얼굴, 아주 미세한 디테일 |
| 인물·사물 일관성 유지(레퍼런스를 줄 때) | 편집을 반복하면 인물이 조금씩 달라짐 |
| 조명·렌즈·색보정 등 촬영 용어 지시 | 마스크 편집, 조명을 통째로 바꾸는 편집 |
| 인포그래픽·다이어그램·레이아웃 | 데이터가 들어간 도표의 사실 정확도 |
| 여러 문장으로 나눈 복합 지시 | 이미지를 아주 많이 섞을 때의 안정성 |

출력물에는 SynthID 워터마크가 들어갑니다.

## 프롬프트 구조 — 이 순서로 씁니다

Google 이 제시하는 요소는 다섯 개입니다. **주제 → 동작 → 장소 → 구도 → 스타일.**

| 순서 | 요소 | 쓰는 내용 |
|---|---|---|
| 1 | 주제 | 누가/무엇이. 나이·체형·의상·소재까지 구체적으로 |
| 2 | 동작 | 무엇을 하고 있는가, 자세와 시선 |
| 3 | 장소 | 배경, 시간대, 날씨, 공간의 재질 |
| 4 | 구도 | 샷 크기, 카메라 각도, 화면 안 배치, 비율 |
| 5 | 스타일 | 매체, 렌즈·조명, 색보정, 필름 질감 |

앞에 오는 것이 강하게 걸립니다. **가장 중요한 것을 첫 문장에 둡니다.**
편집·변형 지시는 «생성한다/바꾼다/합성한다» 같은 동사로 문장을 시작합니다.

레퍼런스를 붙일 때는 구조가 하나 더 필요합니다.

> **[레퍼런스별 역할] + [관계 지시] + [새 상황]**
> 예: 「1번 이미지의 인물을 그대로 유지하고, 2번 이미지의 의상 재질만 가져와,
> 해질녘 골목에 서 있는 미디엄 샷으로 만든다.」

레퍼런스가 여러 장이면 **각 장이 무엇을 담당하는지 반드시 지정합니다.**
역할을 안 적으면 모델이 섞어 버립니다.

## 길이와 문체

- **서술문으로 씁니다.** 「젊은 여자, 빨간 드레스, 공원, 8k, 마스터피스」 같은 나열은 나쁩니다.
  「빨간 드레스를 입은 젊은 여자가 공원을 달린다」 처럼 문장으로 씁니다.
- 길이 제한은 사실상 문제가 되지 않습니다. 입력 한도가 수만 토큰 규모입니다.
  다만 **한 문단에 한 덩어리씩** 나눠 쓰는 편이 지시가 더 정확히 걸립니다.
- 구체적일수록 통제력이 올라갑니다. 「정장」보다 「남색 트위드 재킷」, 「머그컵」보다
  「미니멀한 세라믹 머그컵」.
- 여러 지시가 있으면 번호나 줄바꿈으로 나눠 적습니다. 순서대로 처리합니다.
- 한국어 프롬프트도 그대로 이해합니다. 화면에 넣을 글자만 언어를 따로 지정합니다.
- 품질 주문(`8k`, `masterpiece`, `best quality`)은 넣지 않습니다. 효과가 없고 자리만 먹습니다.
  화질은 프롬프트가 아니라 해상도 설정으로 정합니다.

## 해상도 · 비율

| 항목 | 값 |
|---|---|
| 해상도 | 1K · 2K · 4K 세 단계 |
| 비율 | 1:1, 3:2, 2:3, 4:3, 3:4, 4:5, 5:4, 16:9, 9:16, 21:9 |

비율은 설정으로 지정하는 것이 정확합니다. 설정을 못 쓰는 경우에만
「9:16 세로 포스터」처럼 프롬프트 안에 명시합니다. 안 적으면 의도치 않게 잘립니다.

## 레퍼런스 이미지

| 용도 | 장수 |
|---|---|
| 전체 입력 | 최대 14장 |
| 사물 고정밀 유지 | 최대 6개 |
| 인물 일관성 | 최대 5명 |
| 스타일 참조 | 최대 3장 |

인물 일관성은 «정체성 레퍼런스» 를 반드시 함께 넣고, 프롬프트에
「얼굴과 체형은 1번 이미지 그대로 유지한다」처럼 **유지할 것을 명시**합니다.
편집을 거듭할수록 얼굴이 흔들리므로, 변형은 원본에서 다시 시작하는 편이 안전합니다.

## 네거티브 프롬프트

**별도의 네거티브 프롬프트 칸이 없습니다.** `--no` 같은 문법도 없습니다.
제외는 문장 안에서 말합니다. 두 가지 방법이 있고, 앞의 것이 더 잘 듣습니다.

1. **원하는 상태를 긍정문으로 바꿔 쓴다.**
   「차 없음」 → 「차 한 대 없이 텅 빈 거리」.
   「손 이상하게 그리지 마」 → 「두 손을 주머니에 넣고 있다」.
2. 그래도 남을 때만 평서문으로 짧게 덧붙인다.
   「간판 글자 없음. 로고 없음. 화면 밖으로 손이 나가지 않는다.」

부정문을 길게 나열하면 오히려 그 대상을 그립니다. **1번을 우선 씁니다.**

## 화면 안 글자

이 모델의 강점입니다. 세 가지를 지키면 정확도가 크게 올라갑니다.

1. 넣을 문자열을 **따옴표로 원문 그대로** 적습니다. — `"오늘의 특선"`
2. 특정 폰트 이름 대신 **글꼴 계열과 무게**를 적습니다. — 「굵은 산세리프, 흰색」
3. **화면 어디에 놓이는지** 적습니다. — 「상단 가운데, 화면 폭의 3분의 2」

줄이 여러 개면 줄마다 따로 지정합니다. 작은 글자와 잔글씨는 여전히 틀립니다.
중요한 문구는 크게 배치하고, 결과는 눈으로 확인합니다.

## 잘 듣는 표현 · 피할 표현

| 잘 듣습니다 | 피합니다 |
|---|---|
| 「골든아워 역광, 긴 그림자」 | 「예쁜 조명」 |
| 「3점 소프트박스 조명」 / 「명암 대비가 강한 키아로스쿠로」 | 「드라마틱하게」 |
| 「로우앵글, 얕은 심도(f/1.8)」 | 「멋진 앵글」 |
| 「광각 렌즈」 / 「매크로 렌즈」 / 「미디엄 풀샷, 중앙 배치」 | 「좋은 구도」 |
| 「1980년대 컬러 필름, 약한 입자감」 | 「빈티지 느낌」 |
| 「차갑게 죽인 틸 톤의 시네마틱 색보정」 | 「영화 같은」 |
| 「남색 트위드」, 「은박 문양이 새겨진 판금 갑옷」 | 「고급스러운 옷」 |
| 「1번 이미지의 인물, 2번 이미지의 배경」 | 레퍼런스 역할 미지정 |
| 「~을 제거하고 나머지는 그대로 둔다」 | 「조금 더 예쁘게」 |
| — | `8k`, `masterpiece`, `ultra detailed` 등 품질 주문 |
| — | 쉼표로만 이어붙인 태그 나열 |

## 편집 지시

- 직접적으로 짧게 씁니다. — 「남자의 넥타이를 초록색으로 바꾼다」
- **바뀌지 않아야 할 것을 함께 적습니다.** — 「나머지 구도와 조명은 그대로 유지한다」
- 한 번에 하나씩 고칩니다. 큰 변경 여러 개를 한 프롬프트에 담으면 부자연스러운 자국이 남습니다.
- 대화식으로 이어서 다듬는 것이 다시 뽑는 것보다 결과가 좋습니다.

## 템플릿

```
[주제] 30대 초반 남자. 짧은 흑발, 각진 턱선. 남색 트위드 재킷과 흰 셔츠.
[동작] 창밖을 향해 반쯤 몸을 돌린 채 서 있다. 시선은 화면 밖 왼쪽.
[장소] 늦은 오후의 낡은 사무실. 블라인드 사이로 먼지가 떠 있다.
[구도] 미디엄 샷, 눈높이, 인물은 화면 오른쪽 3분의 1에 배치. 16:9.
[스타일] 시네마틱. 창에서 들어오는 강한 역광과 긴 그림자.
        35mm 렌즈, 얕은 심도. 차갑게 죽인 틸 톤 색보정, 약한 필름 입자.
```

레퍼런스가 있을 때는 맨 앞에 한 줄 더 붙입니다.

```
[레퍼런스] 1번 = 인물의 얼굴과 체형(그대로 유지). 2번 = 의상 재질만 참조.
          3번 = 공간의 색감과 조명 분위기만 참조.
```

## 마지막 점검

- 태그 나열이 아니라 문장인가
- 주제 → 동작 → 장소 → 구도 → 스타일 순서인가
- 조명·렌즈·색보정이 구체적인 말로 들어갔는가
- 부정문 대신 긍정문으로 바꿔 썼는가
- 레퍼런스마다 역할을 지정했는가
- 유지해야 할 것(정체성·구도)을 명시했는가
- 품질 주문어가 남아 있지 않은가
