## 핵심 규칙

모델·버전마다 갈리는 것은 표(`lib/modelRules.ts`)가 들고 있습니다. 여기서는 **늘 지킬 것**만.

1. **대사 문법은 모델마다 다릅니다.** 앱이 `이름: "대사" — 지시` 를 읽어 그 모델의 모양으로
   다시 빚습니다(콜론·대괄호 라벨·`<d>` 태그·`{}` 중괄호·구 단위). **모양을 풀어 쓰지 마세요.**
2. **소리를 못 만드는 모델에 대사를 보내면** 자막으로 박히거나 그냥 버려집니다.
   그때는 대사를 빼고 **입 모양과 표정만** 적습니다.
3. **부정문이 안 통하는 모델이 있습니다**(Runway). 「~하지 마세요」가 오히려 그것을 부릅니다.
   같은 뜻을 **긍정으로 뒤집어** 적습니다 — `not blurry` → `sharp focus, high detail`.
4. **네거티브 칸이 있어도 쓰는 법이 다릅니다.** Veo 의 네거티브 칸에는 `no`·`don't` 를
   쓰지 말고 **명사만** 나열합니다.
5. **한 번에 나오는 길이를 넘기지 마세요.** 넘치면 잘리거나 배속으로 돌아갑니다.
6. **카메라 지시를 두는 자리**가 갈립니다 — 앞이 잘 먹는 모델(Veo 계열)과
   맨 뒤가 맞는 모델(Kling)이 있습니다.


# 공통 규칙과 모델별 규칙

모델마다 프롬프트 규칙이 다릅니다. 공통·모델별·판별로 갈라 두어야 쓸 모델에 맞는
프롬프트가 나오고, API 로 한꺼번에 뽑을 때도 같은 규칙이 실립니다.

이 문서는 **어느 규칙이 어디에 있는지**를 정하는 문서입니다. 규칙 자체는
각자의 자리에 있습니다.

## 세 층으로 나눕니다

| 층 | 어디에 | 무엇이 |
| --- | --- | --- |
| **공통** | `techniques/` | 모든 모델에 통하는 것. 앞쪽이 무겁다 · 한 컷에 연기 하나 · 감정 이름만 적지 마라 · 색으로 묶기 |
| **모델·버전** | `models/<id>.md` 와 `lib/modelRules.ts` | 그 판에서만 갈리는 것. 대사 문법 · 소리 · 네거티브 자리 · 최대 길이 |
| **플랫폼** | `platforms/` | 보내는 곳의 사정. 마그니픽의 `@태그`, ComfyUI 의 노드 |

**공통에 적을 것을 모델 문서에 베끼지 마세요.** 모델을 하나 더할 때마다 같은 말을
또 적게 되고, 고칠 때 한 곳을 빠뜨립니다. 반대로 **한 모델에서만 참인 것을 공통에
올리면** 다른 모델에서 틀린 프롬프트가 나갑니다.

## 버전은 반드시 나눕니다

같은 이름이라도 **판이 다르면 다른 모델**입니다.

실제로 저지른 잘못입니다. Kling **2.6** 공식 문서에 적힌 제약
(「중국어·영어만 소리로 낸다」)을 **3.0** 문서에 그대로 옮겨 적었습니다.
3.0 은 한국어도 잘 냅니다 — 연기가 좀 과장될 뿐입니다.

그래서 규칙표에는 판마다 줄이 따로 있습니다. **새 판이 나오면 줄을 고치지 말고
새로 더하세요.** 옛 판을 쓰는 사람이 있고, 무엇보다 「이 판은 이랬다」가 남아야
같은 사고가 다시 안 납니다.

## 왜 문서 말고 표도 두는가

규칙은 이미 글로 적혀 있습니다. 그런데 글은 **사람과 LLM 만** 읽습니다.
우리 앱이 규칙으로 조립하는 길(`buildCutVideoPrompt`)과 API 로 보내는 길은
그 글을 못 읽습니다. 그래서 **기계가 쓰는 사실**만 `lib/modelRules.ts` 에
표로 두었습니다. 문서는 「왜 그런가」를 맡습니다.

**둘이 어긋나면 표가 사실입니다.** 문서를 고쳤으면 표도 고치세요.

표가 들고 있는 것은 이렇습니다.

| 칸 | 무엇을 정하는가 |
| --- | --- |
| `audio` | 소리를 만드는가. `always` 는 **끌 수 없다**는 뜻(Veo) |
| `dialogue.syntax` | 대사를 적는 모양 — 따옴표 · 콜론 · 대괄호 라벨 · 별도 블록 · 태그 · 구 단위 |
| `dialogue.korean` | 한국어를 한국어로 말하는가, 영어로 번역하는가, 아예 무음인가 |
| `negative` | 네거티브 칸이 있는가 · 본문에 적는가 · **부정문 자체가 안 통하는가** |
| `maxSeconds` · `bestSeconds` | 한 번에 나오는 길이와, 대사가 든 컷의 권장 길이 |
| `camera` | 카메라 지시를 앞에 두는가 뒤에 두는가, 대괄호로 따로 적는가 |
| `quirks` | 그 판에서만 겪는 것 |

## 대사는 이 모양 그대로 적으세요

우리 앱은 컷의 «대사 · 연기 지시» 를 **고른 모델의 문법으로 고쳐** 영문 프롬프트에
싣습니다(`lib/dialogueShape.ts`). API 로 받아 쓸 때도 같은 모양이라야 합니다 —
모양이 어긋나면 대사가 서술로 읽혀 소리가 안 나거나, 태그가 글자로 화면에 그려집니다.

| 모양 | 이렇게 적습니다 |
| --- | --- |
| 콜론 (Veo) | `수화 says: 그만해.` — **따옴표를 쓰지 마세요.** 따옴표가 자막을 부릅니다 |
| 대괄호 라벨 (Kling) | `[수화, 낮고 눌린 목소리]: "그만해."` |
| 별도 블록 (Sora) | 본문 뒤에 `Dialogue:` 줄, 그 아래 `- 수화 says, "그만해," 낮게.` |
| `<d>` 태그 (MiniMax-H3) | `수화 (S1) says: <d>[Korean] 그만해.</d> 낮게.` — 태그 **안에는 대사 원문만**, 연출·음색은 전부 밖에 |
| `{}` 중괄호 (Seedance) | `수화 says {그만해.} 낮게.` — `<d>` 를 쓰면 태그가 글자로 그려집니다 |
| 구 단위 (LTX) | `수화 speaks, 낮게: "그만해."` — 연기 지시를 대사 **사이에** 둡니다 |
| 따옴표 + 속성 (Wan) | `수화 says, "그만해," 낮게.` |

화자 번호(`S1`·`S2`)는 **이름당 하나**로 고정합니다. 같은 사람이 두 번 말하는데
번호가 달라지면 생성기가 두 사람으로 읽어 목소리가 바뀝니다.

## 특히 조심할 세 갈림길

### ① 소리를 못 만드는 모델에 대사를 보내면

소리가 안 나는 데서 끝나지 않습니다. **자막으로 박히거나 그냥 버려집니다.**
그때는 대사를 빼고 **입 모양과 표정만** 적고, 소리는 나중에 립싱크로 붙입니다.

우리 앱은 모델을 골라 두면 이걸 알아서 갈라 줍니다 — 컷 영상 프롬프트가
「말하는 입 모양과 표정만 연기하고, 화면에 글자는 넣지 않습니다」로 바뀝니다.

### ② 부정문이 안 통하는 모델

Runway 가 그렇습니다. 「~하지 마세요」를 보내면 **오히려 그것이 나옵니다.**
같은 뜻을 긍정으로 뒤집어야 합니다.

| 통하지 않음 | 이렇게 |
| --- | --- |
| `not blurry` | `sharp focus, high detail` |
| `No camera movement.` | `Locked camera. The camera remains still.` |
| `no text, no subtitles` | `filling the whole frame with the image itself` |

### ③ 네거티브 칸이 있어도 쓰는 법이 다릅니다

Veo 는 칸이 있는데 **그 칸에 「no」를 쓰면 안 됩니다.** 원치 않는 것을
**명사로만** 나열합니다. 그리고 그 칸은 Vertex AI 에만 있습니다.

## 새 모델을 더할 때

1. `lib/modelRules.ts` 에 줄을 더합니다. **버전까지 적습니다.**
2. 갈리는 것이 많으면 `prompts/models/<id>.md` 에 문서를 쓰고 `doc: true` 로.
   갈리는 것이 적으면 `quirks` 몇 줄로 충분합니다.
3. **공통 규칙은 베끼지 않습니다.** 그건 `techniques/` 것입니다.
4. 확인 안 된 것은 적지 마세요. 추측으로 채운 규칙은 틀린 프롬프트를 만듭니다.
