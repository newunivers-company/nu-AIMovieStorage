# 개발 환경 메모

## 어느 창에서 돌릴 것인가

**cmd 와 Git Bash 둘 다 됩니다.** PowerShell 만 `pnpm.ps1` 실행 정책에 막힙니다.

예전에는 Git Bash 에서 Rust 링크가 깨졌습니다. 원인이 고약했어요.

Git Bash 는 **이름에 괄호가 든 환경변수를 통째로 빼 버립니다.** MSYS 가 그런
이름을 못 다뤄서 `ProgramFiles(x86)` 이 사라집니다. 그러면 빌드 스크립트의
`%ProgramFiles(x86)%\...\VsDevCmd.bat` 이 빈 경로가 되어 **조용히 실행되지
않고**, MSVC 링커가 PATH 에 안 올라갑니다.

그 상태에서 Rust 는 `link` 를 찾다가 Git Bash 안에 들어 있는 리눅스 도구
`C:\Program Files\Git\usr\bin\link.exe` 를 집습니다. 하드링크를 만드는
coreutils 명령인데 이름만 같습니다. 그래서 크레이트 600개를 다 컴파일한
다음에야 «extra operand» 라는 알 수 없는 오류가 쏟아집니다.

지금은 `scripts/tauri.mjs` 가 그 변수에 기대지 않고 **Visual Studio 를 직접
찾습니다** (vswhere 우선, 없으면 흔한 설치 경로). 그리고 컴파일을 시작하기
전에 `scripts/check-linker.mjs` 가 링커가 제대로 잡혔는지 확인합니다.
잘못 잡혔으면 600개를 컴파일하기 전에 그 자리에서 멈춥니다.

## 명령

```
pnpm install          한 번만
pnpm check            타입 검사
pnpm dev              웹으로만 (127.0.0.1:3000)
pnpm dev:desktop      Tauri 창으로 띄우기
pnpm build:desktop    설치본 만들기
```

`dev:desktop` 은 vite 를 알아서 띄웁니다. `pnpm dev` 를 따로 켜 두면
3000번 포트가 물려서 실패합니다.

## 되찾은 설정들

사고로 잃어 다시 세운 것이라 근거를 남겨 둡니다.

- `package.json` — 기록에서 전문을 되살렸습니다. 의존성 53 + 개발 21
- `tauri.conf.json` — 전문 복원. 창 1440×960, devUrl 127.0.0.1:3000
- `vite.config.ts` — `tauri.conf.json` 의 devUrl·frontendDist 에 맞춰 다시 씀
- `tsconfig.json` 의 `"target": "ES2022"` — 되살린 사본에 이 줄이 없어서
  `tsc` 가 ES5 로 잡았고, `[...new Set()]` 같은 문법이 전부 오류였습니다
